# Internationalization (English / Russian)

> Status: **implemented** (Phase 3). Code: [`libs/client/i18n`](../../libs/client/i18n).
> Decision: [ADR-009](../decisions/ADR-009-i18n.md).

## What is translated where

| Text                                                     | Source                                                                       |
| -------------------------------------------------------- | ---------------------------------------------------------------------------- |
| UI texts (navigation, buttons, headings, states, errors) | Transloco translations in `libs/client/i18n/src/lib/translations/{en,ru}.ts` |
| Country and capital names                                | The dataset (`name.en/ru`, `capital.en/ru`), via `displayAnswer()`           |
| Numbers with nouns ("195 стран")                         | `wqPlural` pipe + `Intl.PluralRules`                                         |

No user-facing literal strings live in component templates or code, except
product names that are the same in every language.

## Runtime behaviour

- The language can be changed at runtime in Settings; the UI re-renders immediately and the choice is stored.
- **Default language:** the first supported language in `navigator.languages`
  (`detectLocale`), otherwise English.
- `<html lang>` follows the active language (important for screen readers and
  for the iOS dictation keyboard in Hard mode).
- **Missing keys** fall back to English. In development they are also logged.

## Translation files

Translations are **TypeScript modules**, not JSON over HTTP:

- `en.ts` defines the key structure. `ru.ts` is typed as `TranslationShape`,
  so a missing or extra key is a **compile error**.
- The loader imports them with `import()`. esbuild emits one small chunk per
  language (≈ 1 kB transferred), bundled with the app. This works offline,
  inside Capacitor, and inside federated remotes, without depending on an
  assets URL.

Conventions:

- keys are grouped by screen, then by element (`settings.appearance.dark`);
- placeholders use `{{name}}`;
- countable phrases have `one`, `few`, `many` and `other` children in every language.

## Plurals

Russian needs three plural forms (1 страна, 2 страны, 5 стран), English two.
Instead of adding an ICU message-format plugin, `PluralPipe` asks the standard
`Intl.PluralRules` for the category and picks the matching key:

```html
{{ 'counts.countries' | wqPlural: 195 }}
<!-- 195 countries / 195 стран -->
```

## Tests

- **Key parity:** every language has exactly the English keys.
- **No empty values.**
- **Same placeholders in every language:** a Russian text cannot silently drop `{{count}}`.
- **Russian texts contain Cyrillic.** This catches a copied, untranslated
  English value; product names are the only exceptions.
- Plural categories for both languages, and the pipe with the real translations.
- Loader: both languages load without HTTP; unsupported languages are rejected.
- Component and E2E tests switch the language and assert real Russian texts.

## Adding a language

1. Add the code to `LOCALES` in `libs/quiz/domain/src/lib/vocabulary.ts`.
2. Add `name`/`capital` values for all 195 countries in the dataset. The
   dataset validation and tests will list any that are missing.
3. Create `translations/<code>.ts` typed as `TranslationShape`, and register
   it in `TRANSLATIONS` in `i18n.providers.ts`.
4. Add the language to the Settings page, then extend the parity tests.
