# Installing the web app (PWA)

> Status: ✅ the app can be added to a phone's home screen, opens without
> browser chrome and works offline. This is how World Quiz is used on a
> phone; the native iOS build (`docs/deployment/ios.md`) exists for the App
> Store route, which needs a paid Apple account.

## What makes it installable

| Piece                                       | Where                                    |
| ------------------------------------------- | ---------------------------------------- |
| Manifest (name, icons, colours, start page) | `apps/shell/public/manifest.webmanifest` |
| Icon, one drawing                           | `apps/shell/public/icon.svg`             |
| Icon, rendered PNGs                         | `apps/shell/public/icons/` (see below)   |
| Service worker (offline)                    | `apps/shell/public/service-worker.js`    |
| Registration                                | `apps/shell/src/app/service-worker.ts`   |
| Tags iOS reads                              | `apps/shell/src/index.html`              |

`display: standalone` is what removes the address bar and the toolbar — the
reason the fourth answer used to be cut off on a phone — and `start_url`
opens the app on Home instead of the marketing route.

**The icons are generated, not drawn by hand four times**:

```bash
node tools/scripts/render-icons.mjs   # after changing icon.svg
```

It renders 192, 512, a maskable 512 (Android may crop an icon to a circle,
so the drawing keeps clear of the edges) and a 180 for iOS, using macOS's
`sips`. The PNGs are committed, so a build needs no image tooling.

## How offline works

The service worker is written by hand rather than generated by Angular's:
this app is three deployments on three origins (the shell and the two quiz
remotes), and Angular's builder only knows the files of the one it builds.
The rules are about kinds of request, so a remote's files are treated
exactly like the shell's:

1. **The API (`/v1/…`) is never cached.** A score or a leaderboard has to be
   the server's current answer. Playing offline is unaffected: finished
   quizzes live in IndexedDB and are sent when the network returns
   (ADR-006).
2. **Pages: network first, cache as the fallback.** A deployment is picked
   up on the next visit; without a network the app still opens.
3. **The files a deployment rewrites: network first** (the `MUTABLE` list —
   `config.json`, `federation.manifest.json`, a remote's `remoteEntry.json`,
   `manifest.webmanifest`). Their names never change while their contents
   do, so cache-first would keep an installed app on the previous
   deployment's API address and remote URLs until someone cleared the site's
   data. `loadRuntimeConfig()` asking for `config.json` with
   `cache: 'no-cache'` does **not** help: that concerns the browser's HTTP
   cache, which is never consulted when a worker answers from Cache Storage.
4. **Everything else: cache first.** Scripts, styles and flags carry a hash
   in their name, so a new build asks for new names and the old entries go
   with the old cache (`world-quiz-v1` → bump the name to drop it).

The rules are tested by running the worker: `service-worker-rules.spec.ts`
reads the file and executes it against a fake `caches`/`fetch`, because an
answer from the wrong place is invisible until an installed app is stuck on
an old deployment.

**Not registered on `localhost`**: a worker serving yesterday's chunk while
the dev server rebuilds is a confusing afternoon. To see it working, serve a
production build on `127.0.0.1` (`nx run shell:serve-static`), which the
registration treats as a real host.

## Installing it

- **iPhone (Safari)**: open the app's address → Share → _Add to Home
  Screen_. Chrome on iOS offers the same through its own share menu. The app
  then opens full screen, keeps its data, and the sign-in survives restarts.
- **Android (Chrome)**: the browser offers _Install app_; the maskable icon
  is used there.
- **Desktop Chrome or Edge**: an install icon appears in the address bar.

## What it does not give

Vibration (no taptic engine in a browser), a place in the App Store, and
Apple's push notifications without extra work. The native build covers the
first two; the third is not planned.
