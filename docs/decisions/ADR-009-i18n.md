# ADR-009: Runtime i18n with Transloco and bundled translation modules

## Status

Accepted (2026-09-17)

## Context

The whole UI must be available in English and Russian, switchable in
Settings without restarting, offline, inside a Capacitor iOS app and inside
Native Federation remotes. More languages may follow. Russian needs three
plural forms. Country and capital names already come from the dataset.

## Decision

- Use **Transloco 8** (`@jsverse/transloco`) for runtime translation.
- Store translations as **TypeScript modules** (`en.ts` defines the shape,
  other languages are typed against it) and load them with dynamic `import()`
  through a custom `TranslocoLoader`. No HTTP loading.
- Handle plurals with the platform's **`Intl.PluralRules`** and a small
  `wqPlural` pipe, not with an extra message-format plugin.
- Default to the device language; the user's choice is stored by `SettingsStore`.

## Alternatives

| Alternative                                     | Why not                                                                                                                                                                                                                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Angular built-in i18n** (`@angular/localize`) | Compile-time: one build per language, and switching reloads a different bundle. With three federated apps and Capacitor, that multiplies builds and complicates runtime switching. It is excellent for SEO/SSR sites, which the app is not. |
| **ngx-translate**                               | Mature, but less active; fewer modern features (signals, scoped lazy loading, typed setup)                                                                                                                                                  |
| **JSON files over HTTP** (Transloco default)    | Depends on an assets URL, which is fragile across federated remotes and requires network or careful Capacitor asset setup; no compile-time key checks                                                                                       |
| **ICU message format plugin**                   | Powerful, but a second syntax and another dependency for two plural phrases                                                                                                                                                                 |

## Consequences

**Positive**

- Instant language switching, offline, with tiny lazy chunks per language.
- Missing or extra keys are compile errors; placeholder mismatches fail tests.
- No extra plural dependency.

**Negative**

- Translations live in code, so translators need a developer workflow (or an
  export script later).
- Runtime translation has a small cost compared to compile-time i18n (negligible at this size).
- Keys are strings in templates; a typo in a key is only caught by tests and
  the dev-mode missing-key log, not by the compiler.

## Rationale

Runtime switching and federation are hard requirements, which rules out
compile-time i18n. Bundled, typed translation modules keep Transloco's
flexibility while removing its only fragile part for this app: HTTP loading.
